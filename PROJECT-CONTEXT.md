## 3. Architecture and data flow

**Entry point:** `src/index.js` → `src/App.js`.

`App.js` (Confirmed, read in full):

- **Router:** `BrowserRouter` with a computed `basename`. On GitHub Pages the
  app lives under `/iZainIqbal`; the CRA dev server serves at `/` while still
  setting `PUBLIC_URL`, so the basename is only applied when
  `window.location.pathname` actually starts with it:
  ```js
  const basename = publicUrl && window.location.pathname.startsWith(publicUrl)
      ? publicUrl : "/";
  ```
- **Routes:** `/`, `/services`, `/projects`, `/about`, `/handman`,
  `/experience`, `/certificates`, `/contact`, and `*` → `NotFound`.
- **Code splitting:** every route except `Home` is `React.lazy`-loaded, wrapped
  in `<Suspense>` with a spinner fallback (`PageFallback`).
- **Layout:** a skip-to-content link → `Header` → `<main id="main">` → `Footer`.
- **`ScrollToTop`** resets scroll on pathname change; **`RouteMeta`** sets
  per-route meta tags.
- **The home page composes other pages** in limited mode:
  `<Home/>`, `<Services limit={3} showSeeAll/>`,
  `<Projects limit={3} hideOlder showSeeAll/>`, `<About compact/>`. So those
  components take props that change their density — changing one affects two
  places.

**Data flow:** `src/data/projects.js` exports `featuredProjects` and
`olderProjects`; `src/components/projects.js` imports them
(`import { featuredProjects, olderProjects } from "../data/projects"`) and
renders. Every project uses one shape, and `links` is always an array whose
first entry renders as the primary CTA. Image paths are built from
`process.env.PUBLIC_URL` so they resolve under the Pages subpath.

**External services:** EmailJS (`@emailjs/browser`) for the contact form —
the only runtime integration. There is no backend, no API, no database.

**SPA fallback:** GitHub Pages serves static files, so a deep link like
`/projects` would 404 on refresh. `public/404.html` is the fallback that hands
the route back to the router.

## 5. How to run and use it

Prerequisites: Node.js + npm. No credentials needed to run or build; the
EmailJS values only make the contact form functional.

```bash
npm install            # once
cp .env.example .env   # then fill in the three REACT_APP_EMAILJS_* values

npm start              # dev server at http://localhost:3000
npm test               # jest via react-scripts (watch mode; CI=true for one pass)
npm run build          # production build into build/
npm run deploy         # predeploy runs build, then gh-pages -d build
```

**Deployment is `npm run deploy` and nothing else.** It regenerates the
`gh-pages` branch, which is what GitHub Pages serves. Pushing to `devs` does
**not** update the live site.

Live URL: <https://izainiqbal.github.io/iZainIqbal/>

## 6. Configuration and environment

| Variable | Purpose | Required |
|---|---|---|
| `REACT_APP_EMAILJS_SERVICE_ID` | EmailJS service | only for a working contact form |
| `REACT_APP_EMAILJS_TEMPLATE_ID` | EmailJS template | same |
| `REACT_APP_EMAILJS_PUBLIC_KEY` | EmailJS public key | same |

**These are not secrets, by design.** `REACT_APP_*` values are inlined into the
production JS bundle at build time and are readable by anyone who loads the
site. The EmailJS public key is public by definition. Abuse control belongs in
the EmailJS dashboard (**Allowed Origins** + captcha), **not** in hiding these
values. `.env` stays untracked regardless (`.gitignore` covers `.env` and
`.env.*.local`); commit `67a5481` untracked it after it was once committed.

`homepage` in `package.json` is configuration too — see §9.

## 8. Operational and safety rules

- **`npm run deploy` is the only thing that publishes.** It force-regenerates
  the `gh-pages` branch. Treat it as an outward-facing action — it changes a
  public website.
- **Never hand-edit the `gh-pages` branch**; it is generated output and the
  next deploy overwrites it.
- The repo is public (it is a GitHub profile repo). **Nothing secret may be
  committed** — and `REACT_APP_*` values would be public even if it weren't.
- `README.md` is the **public GitHub profile page**. Edits to it are visible on
  the profile immediately on push; it is not a place for build notes.
- Deploy from a build that passes tests — there is no CI gate in the repo, so
  `npm run deploy` will happily publish a broken site.

## 9. Important decisions and gotchas

- **`homepage` must stay `https://izainiqbal.github.io/iZainIqbal` with exact
  casing.** A lowercase value (`/izainiqbal`) builds asset paths that 404 on
  the live site. (`DEVELOPMENT.md`, and the workspace `CLAUDE.md` repeats it.)
- **Pushing to `devs` does not update the live site.** Only `npm run deploy`
  does. This is the single most common "why didn't my change appear" cause.
- **Project data location — resolved conflict.** `DEVELOPMENT.md`
  §Customization and `gn/CLAUDE.md` both say "Update project data in
  `src/components/projects.js`". **The code disagrees and wins:**
  `src/data/projects.js` holds the data (180 lines starting with
  `const publicUrl = ...`, exporting `featuredProjects`/`olderProjects`), and
  `src/components/projects.js:4` imports from it. Commit `193c46f`
  ("refactor: extract project data to src/data") made the move; the prose was
  not updated. **Edit `src/data/projects.js`.** Certificates were *not* moved —
  `src/components/certificates.js` still holds that data, so the prose is
  correct for certificates only.
- **The Jest `moduleNameMapper` block in `package.json` is load-bearing** for
  React Router 7 under CRA. Do not remove it.
- **The `basename` computation in `App.js` is deliberately conditional** so the
  same build works on the dev server (`/`) and on Pages (`/iZainIqbal`).
  Hardcoding either one breaks the other.
- **Broken images render a visible fallback**, not an empty frame
  (`PhoneFrame` in `src/components/projects.js` tracks an `errored` state and
  shows an "Screenshot unavailable" placeholder). This is intentional — commit
  `193c46f` calls it "honest image states" — so a missing export is caught
  rather than hidden. Do not "fix" it by silencing the fallback.
- **`public/404.html` is required** for deep links to survive a refresh on
  GitHub Pages. Deleting it breaks every route but `/`.
- **`limit` / `hideOlder` / `compact` / `showSeeAll` props** mean the same
  component renders on both the home page and its own route. Test both.
- Dependencies are pinned exactly, per the workspace's security rules — keep it
  that way when adding packages.
